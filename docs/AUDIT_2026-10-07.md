# PostDeck Audit + Plan - 2026-10-07

Scope: whole app after a 7-week gap. Read BUILD_STATUS, CHANGELOG, SPEC, the 2026-09-02 audit;
strong-model frontend and backend code reviews; competitor research (Buffer, Publer, Hootsuite,
Sprout, Later, Typefully); a live walkthrough of a sandboxed copy (snapshot DB, dry-run, worker
and sync off, port 4599). Full working notes: frontend review, backend review and competitor
research were kept in the session scratchpad; everything that matters is condensed here.

## Verdict

The engine is sound (331 tests green, safety rails real). The product is not. Usage tells the
story: **26 posts ever, none created since 2026-08-13, 7 of 26 stuck in failed states, 9 feature
tables never used once.** The app grew 23 waves of features faster than the core loop got
trustworthy. CB doesn't have a "design" problem first; he has a trust problem (posts fail
silently, edits shift times, saves duplicate) wearing a design problem's clothes (13 nav items,
10 ways to start a post, nothing updates in place).

Order of work: make it trustworthy, then make it feel live, then make it small.

## Findings

### P0 - trust breakers (fix before anything else)

| # | Finding | Where | Fix |
|---|---|---|---|
| T1 | **Duplicate-publish risk.** `request()` retries network errors/timeouts up to 5x on every method, including `POST /v2/posts`. If Blotato accepted the first one, each retry is another live post; the worker then retries again next cycle. Blotato can't delete. | `blotato.js:96-104`, `worker.js:262-276` | Never auto-retry post creation on timeout/network/5xx. Mark `needs_check` and surface it. |
| T2 | **failed_verify is a dead end.** Verify quits after 6 polls (~25 min) with no `error_message`; posts 19, 21, 42 were still "in-progress" and are very likely live. Post 1 was marked submitted with a null submission id. UI: Needs Attention skips failed_verify, the drawer returns early with no actions, no retry/mark-posted offered. | `worker.js:248-257, 486-519`; `app.js:1330, 2720` | Read `publicUrl`; poll with backoff up to 24h; store last Blotato state; refuse null ids; `/recheck` route; failed + failed_verify in Needs Attention with Recheck / Mark as posted / Retry / Move to draft. |
| T3 | **Editing a scheduled post shifts it +4h on every save.** UTC string sliced into a local `datetime-local`. Also Composer queue path. | `app.js:4549, 5456` | Use existing `isoToLocalInput()`. |
| T4 | **Calendar puts evening posts on the next day.** Days keyed by UTC date. | `app.js:1874, 1888, 1950, 2082` | Use existing `dateKeyLocal()`. |
| T5 | **Rescheduling from the calendar drawer always 409s.** Scheduled posts are `scheduled_local`; drawer sends `status:'approved'`; transition table forbids it. Same for Review "Add to queue" then "Approve & next". | `app.js:2768, 4128, 4151`; `server.js:123, 541` | Treat approved/scheduled_local as one state for PATCH (time edits allowed, no status change needed). |
| T6 | **publish_at stored as whatever text arrives** (mixed `Z`, no-ms, no-zone). String comparisons in worker; raw value sent to Blotato. Agent-written zone-less times can go out at the wrong hour. | `server.js:524, 557`; `agent.js:440, 467`; `worker.js:246, 313, 519`; `queue.js:153` | Normalize to UTC ISO on every write; migrate existing rows; compare as dates. Fixes queue double-booking too. |
| T7 | **Short-notice posts flagged "missed window" instead of sent.** A post approved for 3 min out is first seen after its time. Flag also overwrites a real handoff error. | `worker.js:304-329` | Hand off immediately on approve; 15-min grace. |
| T8 | **Normal use creates duplicate posts.** Composer Save/Schedule always INSERTs; Request image auto-saves first; Quick Compose retry after partial failure re-creates; Review "Open in composer" copies. | `app.js:6069-6094, 5220, 3740-3890, 4204` | One post id per editing session; saves become PATCH after the first; buttons disable in flight. |
| T9 | **Origin guard lets `Origin: null` through.** Sandboxed iframe / no-referrer form + `text/plain` body can hit publish-now. | `server.js:160` | Reject `null`; require JSON content-type on writes; test it. |
| T10 | Queue and agent approve bypass the approve gate (UTM, TikTok checks). | `server.js:2098-2142`; `agent.js:663` | Route both through the same approve function. |
| T11 | CHolmesIV Facebook account has no pageId. | accounts id 2 | Use `listSubaccounts` to pick the page; fix Di-Hy FB the same way. |

### P1 - why it feels dead

- Every navigation and every post-action refresh swaps the view to "Loading…": scroll jumps to
  top, entrance animation replays (`app.js:866-867`, `router()` calls at 4398-4567). Scroll
  position also leaks between routes (Review -> Composer opened mid-page).
- Only the Calendar has a refresh hook (`currentCalendarReload`); saves from Home, Quick
  Compose, Review leave the screen stale. Nav pill polls every 60s.
- Home fires ~35 requests (posts, analytics x2, profiles x4, per-brand queue/tone x2) and
  repeats them on brand change.
- No optimistic updates, no autosave, no undo. 13 native `confirm()/alert()/prompt()`.
- Unsaved work is silently lost: chat-agent actions re-render over an open Composer; Esc in
  the drawer discards edits; Quick Compose dirty-check ignores the idea field.
- Errors swallowed without a toast in Composer Save, calendar filters, brand switches, Ideas,
  Review.
- Raw internal names in the UI: `scheduled_local`, `failed_verify`, "Worker - last run:
  (unscheduled)".
- Seen in the walkthrough: Quick post modal has a horizontal scrollbar (the "Link in first
  comment" label overflows) and footer clipping; Esc doesn't close it and it survives route
  changes; the floating + does nothing on the Composer route; Settings zone links route to Home.

### P2 - too much app

- 13 nav items + 3 floating buttons. 10 ways to start a post, 5 places to edit/review, 9
  approve/schedule controls, 7 "send" labels for 4 server actions.
- Idea -> scheduled on LinkedIn + Facebook: Quick Compose >= 6 clicks / 6 decisions (accounts
  never preselected, two text boxes, one shared copy for both networks with the FB AI draft
  discarded, no quiet-hours check). Full Composer 7-9 clicks, no date presets.
- ~3k lines / ~40 routes serve tables that have never had a row.

### P3 - structure

- `public/app.js` 9.1k lines; Composer alone ~1.4k. ES-module split is feasible with no build
  step (no inline handlers; ~12 reassigned module globals move into a store object). 27-module
  map exists in the review notes.
- Launcher wipes the previous log each start (`>` not `>>`). Not running = nothing posts, no
  backups (last backup 2026-09-13).
- Media: live posts upload originals, not the resized platform files (and the resizer's size
  choice is wrong: a LinkedIn square sits on disk at 327x327). Alt text never sent. Video is
  base64 in JSON.
- Best-time math sums snapshots and counts future posts (dormant: metrics table empty).

## What the good tools do (borrow list)

Ranked for a solo multi-brand operator. Team features (approvals, inbox, permissions) skipped.

1. **Queue with "Next available" as the default action** (Buffer, Publer, Typefully). No time
   decision per post. PostDeck has the code; zero slots defined, so it's invisible.
2. **Click an empty calendar slot to create**, channel and time prefilled (Buffer, Publer).
3. **Drag to reschedule** (Buffer, Publer, Later). PostDeck has it; T5 breaks the drawer path.
4. **Brand filter on the planner prefills the composer** (Buffer).
5. **One text box first; "Customize per network" opt-in** (Buffer, Hootsuite).
6. **Channel groups**: brand = one click selects its accounts (Buffer).
7. **Live per-network preview beside the editor** (Sprout, Hootsuite, Publer). PostDeck has it.
8. **One planner surface with a status filter** All / Drafts / Scheduled / Sent / Failed
   (Buffer, Publer) instead of separate Review / Calendar / Library / Ops pages.
9. **Failed posts show the reason + one-click retry / reschedule** (Publer, Hootsuite).
10. **Cmd+K + shortcuts** (Typefully). PostDeck has it; low discoverability.
11. **Unscheduled drafts tray** beside the calendar; drag a draft onto a day (Buffer).
12. **Duplicate / reuse** (Hootsuite, Buffer). PostDeck has duplicate-to-brand.
13. **Up to 3 suggested-time chips** (Hootsuite).
14. **Writer-first editor, metadata in a collapsible side panel** (Typefully).

"Live" feel (autosave, in-place updates, undo toasts, skeletons) isn't documented publicly by
any of them; it's our own build discipline, covered in Wave 2.

## Build plan

Each wave ends with suite green, browser QA on a sandbox copy (port 4599, dry-run, worker/sync
off, `POSTDECK_DB_PATH` set), CHANGELOG + BUILD_STATUS, commit on `working`.

**Wave 0 - Trust (strong model, small diffs). ~1 session.**
T1-T11. Add the missing tests (no POST retry on timeout, verify give-up, failed_verify recovery,
Origin null, timestamp normalization, short-notice handoff). Launcher log append. Home warning
when the worker hasn't run in >24h.

**Wave 1 - One editor, no duplicates (strong design, Sonnet assembly).**
Single post drawer used by Planner, Home, Review. Idempotent saves + autosave draft every few
seconds. Esc/route-change guards with "unsaved changes" prompt (custom dialog, not confirm()).
Replace all native dialogs with a custom confirm + undo toast.

**Wave 2 - Feels live (Sonnet, strong review).**
Shared `refreshView()` that patches in place (no "Loading…" swap, keeps scroll/focus); optimistic
status changes; skeletons only on first load; Home request diet (one `/api/home` summary
endpoint); error toasts everywhere; plain-language statuses; fix modal overflow/Esc/FAB/zone
links.

**Wave 3 - Simplify IA (strong design, Sonnet build).**
New nav (above). Planner with status filter + drafts tray + click-to-create + week default.
Create flow: brand-first, accounts preselected, one box + customize, "Next available" default
once slots exist, 3 time chips, quiet-hours check. Seed sensible default slots per brand
(e.g. LinkedIn Tue-Thu 9:30, FB daily 12:00) for CB to accept. Park/remove unused features.

**Wave 4 - Voice per brand.**
Replace the 15 placeholder tones with real rules (from the voice card + brand docs), give
PrimeWright / Lunula / IVision their own voice docs or explicitly inherit CB's.

**Wave 5 - Structure.**
Split app.js into ES modules per the map; delete parked code; fix media resizer + send resized
files and alt text.

**Then:** CB posts for a week from the new flow; we cut whatever he still trips on.
