# PostDeck Full Audit - 2026-09-02

Scope: everything. Local `working` branch (cf65cf3, B22.1) vs GitHub `main` (f14cdfc, B7),
backend (`src/`), frontend (`public/`), worker, AI orchestration (Claude + Codex), tests,
dependencies, docs, repo hygiene, runtime environment on CB's Mac.

Method: strong-model review of `server.js`, `ai.js`, `agent.js`, `worker.js`, `blotato.js`,
`draft.js`, `db.js`, `sync.js`, `env.js`; three parallel Sonnet reviews (frontend, backend/tests,
docs/secrets); live checks against the running instance on 127.0.0.1:4520.

## Verdict

Solid for a solo local tool. Safety rails are real (dry-run default, approve gate, agent
publish gate, path confinement, parameterized SQL, DOM built without innerHTML). The two things
that matter most: the app is running **live** (dry-run off) with **no request-origin check**,
and the "AI provider switcher" only covers two of six AI call paths. Everything else is
maintenance debt, not danger.

## Findings by area

### Security

| # | Sev | Finding | Fix |
|---|---|---|---|
| S1 | HIGH | No Origin/Host check on state-changing routes. The API binds 127.0.0.1 but any web page open in the browser can `fetch('http://127.0.0.1:4520/api/posts/:id/publish-now', {method:'POST'})` (CSRF) and DNS-rebinding defeats the loopback bind. With `BLOTATO_DRY_RUN=0` and `agent_can_publish` available, this reaches a real publish. BUILD_STATUS already lists it under "watch". | `onRequest` hook: reject non-GET requests whose `Origin` is present and not the app's own origin; reject any request whose `Host` is not `127.0.0.1`/`localhost`. |
| S2 | HIGH | Double-submit race. `submitNow()` and the 5-minute `runHandoffPhase()` both read status then `await` network work then write. A click during a sweep can call Blotato twice for one post. `cycleInFlight` only guards the sweep against itself. | In-process claim set around `handoffOne`, plus a status re-read immediately before the network call. |
| S3 | MED | `@fastify/static` 6.12 has two advisories (GHSA-83w8-p2f5-377r path-traversal route-guard bypass, GHSA-8pvw-jcv7-9cmj). Mitigated by `path.basename()` confinement on media, but the plugin still serves `public/` directly. Fix requires Fastify 5. | Upgrade `fastify` 4 -> 5, `@fastify/static` 6 -> 10, `@fastify/multipart` 8 -> 10; run the 317-test suite. |
| S4 | MED | `npm audit`: 5 high (also `brace-expansion`, `fast-uri`, transitive). | `npm audit fix`. |
| S5 | MED | `src/sync.js` defaults **on** and rsyncs `state/social-state.json` to the configured VPS every 15 min whenever the configured ssh key exists. `.env.example` says the opposite ("off unless you set a target"). The hostname and key path are hardcoded in source. It is working as CB intended (logs confirm pushes today) but the default is surprising and the code carries infra identifiers. | Not changed in this pass (Agentic OS depends on it). Move host/key defaults to `.env`, make the doc match the code. Decision for CB. |
| S6 | LOW | `startLogin()` builds an AppleScript string by interpolating the CLI binary path (`POSTDECK_CLAUDE_BIN`). Env-only input, so not exploitable today. | Leave; note. |
| S7 | LOW | Prompts are passed to `claude -p` / `codex exec` as a single argv entry. macOS ARG_MAX is 1 MB; the agent prompt embeds all brands + accounts + history; `redistribute` embeds a blog body (capped at MAX_MARKDOWN_CHARS). No injection risk (execFile, no shell) but a very long prompt would fail with E2BIG. | Move to stdin later; keep the cap. |
| S8 | INFO | Git history is clean: no keys, no `.env`, no `accounts.seed.json`, no DB ever committed. No rotation needed. GitHub repo is **private**, not public. | None. |
| S9 | INFO | Frontend: 168 `innerHTML` hits, all but one are `= ''` clears. The one template (`platformIcon`, app.js:687) interpolates a static icon-path map only. No `eval`, no secrets in `app.js`. | Document the `el()` convention so it survives. |

### Agent orchestrator (Claude <-> Codex, and adding a third)

| # | Finding |
|---|---|
| O1 | `src/ai.js` exposes `runDraft(provider, ...)` but only `draft.js` and `copy_assist.js` call it. `agent.js`, `profiles.js`, `inspiration.js`, `extract.js` each have their own copy of the `claude -p ... --output-format json` shell and envelope parser (six copies of the same 40 lines). The Settings "AI provider" switch therefore has no effect on the chat agent, profile generation, inspiration suggestions or screenshot extraction. |
| O2 | The Codex adapter ignores `model` and `budget`; the Claude adapter ignores nothing. No provider declares capabilities (vision, JSON mode), so the vision path can only ever be Claude. |
| O3 | `POST /api/draft/compare` and `GET /api/ai/status` hardcode `['claude','codex']`. The frontend hardcodes `AI_PROVIDERS` too (app.js:388) and the Settings select. Adding a third provider today means editing five places. |
| O4 | Both providers are subscription CLIs by design (no API keys). There is no HTTP provider kind, so an API-only vendor (xAI/Grok, OpenAI, Ollama) cannot be added without a new abstraction. |
| O5 | `/api/ai/status` spawns two CLIs (`claude auth status`, `codex login status`) on every Composer render with no caching. Measured `claude auth status` at ~0.25 s; Codex is slower. |
| O6 | The chat agent runs up to 3 rounds, each a fresh CLI process (cold start each time). Acceptable; a persistent HTTP provider would be faster for Grok-class calls. |
| O7 | Prompt-injection surface: the agent context includes ingested research notes/examples only via tools, and the publish tools are gated behind `agent_can_publish` (default off) and dry-run. Good. Keep it off unless supervising. |

Spec for the fix: `docs/PROVIDER_LAYER_SPEC.md`.

## Incident during the build

While smoke-testing on port 4599 the session ran `node src/seed.js` once without
`POSTDECK_DB_PATH`, so the idempotent seeder upserted into the live `postdeck.db`. Verified
impact: brand `name`/`voice_doc_path` reset to seed values (colors, logos kept), tone-profile
`voice_rules` reset to placeholders (hard rules kept), PrimeWright profile drafts reset from
`config/profile-seed.primewright.json`. Accounts, posts, metrics, settings untouched. Fix
shipped: `seed.js` now refuses on a populated DB without `--force`. If Settings > Brands/Tones or
Profiles had hand edits, they need re-entering. The daily backup (D1) would have made this a
restore instead of a re-type; it starts with this deploy.
